# Review: plan 11 build (results, review inbox, Weave)

Independent correctness + security review of the uncommitted working tree implementing
`docs/plans/11-results-review-weave.md` (§7 amended spec), against the engineers' reports
(`backend-11-report.md`, `frontend-7-report.md`, `ui-9-report.md`) and the pre-build review
(`review-plan-11.md`). Read-only apart from this file. Weave package checked is the installed
`.venv/lib/python3.12/site-packages/weave` (0.53.x).

## Verdict: **fix-then-ship**

No blocker. Nothing in the gateway's Weave path can carry `ANTIBODY_BACKEND_AUTH`, the gateway bearer,
`X-Antibody-Customer` or a request header into a trace; the feature is off without both the flag and a key;
enabling it cannot change an enforce/shadow decision or make a tool call wait on Weave. The should-fixes are
one real UI bug (stale editor data for up to 30 s when navigating across runs), one unbounded queue under a
Weave outage, and two README sentences that over- or under-state what is sent.

## Security — what was checked and how

**Gateway Weave path** (`chaos/gateway.py`), request → `_after_call` → `_trace` → `gateway.tool_call` → `ToolRuleScorer`:

- The only op inputs are the eight primitives built by `trace_inputs` (`:206-223`): `tool`, redacted `args`, redacted `result`, `decision`, `elapsed_ms`, redacted `turns`, `verified` (ids), `ran`. The op signature (`:227`) is the guard, and `tests/test_weave_integration.py::test_gateway_trace_never_carries_secrets` asserts it. Neither `session` (which holds `backend_auth`, `:45-47` in `toolbus.py`) nor the request headers are parameters. The customer id lives only in the session tuple (`:382`) and the log line (`:405`), never in the trace.
- `self` capture: `_traced_tool_call` is a module function (no `self`). `ToolRuleScorer.score` captures `self` = the scorer object, whose only field is `rules` (the version's `ToolRule`s) — disclosed in README. `apply_scorer` filters call inputs to the scorer signature (`weave/flow/scorer.py:291-314`), so `result`/`decision`/`elapsed_ms` do not reach `score`.
- Exception paths: `_trace` is one `try/except Exception` (`:412-417`) printing the exception type and message. The message can only contain Weave's own error text, not request data. Backend HTTP errors become `str(HTTPError)` ("HTTP Error 401: Unauthorized") with no body or headers (`toolbus.py:204`, `:206`).
- `redact` (`:195-203`): recurses through dicts, lists and tuples; drops keys matching `token|auth|password|passwd|secret|bearer|cookie|credential|api[_-]?key` at every depth; truncates strings > 500. Verified with `test_redact_drops_credential_keys_at_every_depth_and_cuts_long_strings`. It does **not** redact secret-looking *values* under innocent keys (e.g. `{"message": "Bearer abc…"}`); that is inherent to key-based redaction and is what the README's "minus anything named like a credential" says. Not a finding, but worth knowing.
- Opt-in (`:185-192`): `weave_enabled()` requires `ANTIBODY_GATEWAY_WEAVE == "1"` **and** `WANDB_API_KEY`; `tracing()` additionally requires `weave.get_client()`; `init_weave` (`:276-285`) is the only `weave.init` and is behind `weave_enabled()`. Without init, every `@weave.op` is a plain function (`weave/trace/op.py:414`). Covered by `test_gateway_weave_is_off_unless_asked_and_keyed_and_fails_soft`.
- Decision/latency semantics: the decision is made in `toolbus._call_passthrough` (`:182-212`) before `after_call` runs; `_trace` runs after the `ToolCall` is recorded and can only print. `op.call` enqueues to Weave's batch processor, which `put_nowait`s and drops on full (never blocks); scoring is on `_SCORING` (finding 2). Fail-closed on money/mutate is unchanged (`_failed`/`_refused`, `toolbus.py:215-230`).
- Thread id = the agent's `X-Antibody-Session` header (`toolserver.py:118-130`, `gateway.py:413`). This is a value the customer's agent chose, sent to Weave as a thread name. It is not one of our secrets; the README should list it (finding 3).

**`api/attack.py` `record_decision`** (`:136-165`): returns early unless `_weave_ready` (warm-up succeeded), so a keyless process never imports/initialises Weave here; `weave.get_client()` is the only client source, never a new `init`. The route (`api/main.py:401-412`) reads the call id via `store.eval_call_id("live", version)` from the live run's own `cycles.jsonl` — the request supplies only `version` and a ≤500-char note (`ReviewBody`, `:383-385`), so it cannot name another call. Covered by `test_record_decision_writes_a_reaction_and_a_note_only_with_a_ready_client` and `test_review_route_hands_the_decision_to_weave_off_the_request_and_never_fails_on_it`.

**`api/` and the network in keyless tests**: no new module-level `import weave` in `api/` (grep); `api/main.py:66` imports `chaos.gateway`, which imports `weave` as a library (no init). `tests/conftest.py:31-32` sets `ANTIBODY_NO_DOTENV=1` and pops `WANDB_API_KEY`; `warm_weave` returns before spawning its thread without a key (`attack.py:118-120`). The full suite ran keyless in this environment with no network prompt.

## Correctness — Weave items

- **Costs** (`chaos/loop.py:424-444`): `add_cost(llm_id, prompt_token_cost, completion_token_cost)` matches the installed signature (`weave_client.py:2382-2389`, "cost per prompt token"); the table is per million (`chaos/config.py:56-64`) and is divided by `1e6` (`loop.py:437`). `query_costs(llm_ids=…)` signature matches (`:2458-2464`). Wrapped in one `try/except`. `_weave_cost` (`:407-421`) flushes then `get_call(id, include_costs=True)`; failure falls back to the local estimate. **Unverified**: that the `llm_id` keys equal the model string Weave records from the inference endpoint's response (`usage` is keyed by the response's `model` field; if the endpoint echoes a different alias the rows never match and costs show as unpriced). Needs one live run to confirm — SMOKE §80 already tells the tester to compare.
- **Threads**: `episode_thread` (`chaos/target.py:44-52`) mints `session_id` once and enters `weave.thread(session_id)`; `toolserver.register` (`:60-71`) keeps that id; `traced_call_tool` (`:118-130`) enters the same id on the worker thread only when a client exists. Same id end to end; tests `:207`, `:237`, `:253` cover it. `weave.thread` groups, it does not nest across processes — the code comments and README:97 say so correctly.
- **Shared legit Evaluation**: `legit_evaluation` (`chaos/evals.py:136-152`) publishes one object and returns it; `weave.publish` sets `ref` on the same Python object (`weave_client.py:2700`, `set_ref`), so every `run_evaluation(model, <that object>, …)` (`:235-236`, `gate.py:109`) runs the identical ref. The Leaderboard column (`evals.py:168`) uses `evaluation_object_ref`, `scorer_name="judge_scorer"`, `summary_metric_path="passed.true_fraction"` — field names match the installed `LeaderboardColumn` (`builtin_object_classes/leaderboard.py:6-10`) and `true_fraction` is what Weave's auto-summary emits for a boolean (`flow/scorer.py:183-184`). Publishing failure → `ref=None` → no leaderboard, same gate. Tests `:278`, `:341`, `:371`.
- **Prompts**: `publish_prompt` is called from the loop only (`LoopState` and per candidate before its gate; test `:640`); `TargetAgent` reads `_prompt_refs` (`evals.py:27-49`). Fail-soft (`:117-121`). Finding 8 is the wording caveat.
- **Fail-soft**: every plan-11 Weave call site is wrapped (`register_costs`, `_weave_cost`, `publish_prompt`, `legit_evaluation`, `publish_leaderboard`, `EvalRun.rename/url/call_id`, gateway `_trace`, `init_weave`, `record_decision`). `Evaluation.evaluate` itself is not wrapped, but that predates plan 11 and a crash there fails the gate closed (`run_evaluation` docstring, `:230-232`).

## API / store

- **Path safety**: history ids go through `run_dir` (`api/store.py:52-67`): regex, `Path(id).name == id`, `resolve()` containment. `review_inbox` builds `source` from the runs list, not the request (`:495`).
- **Corrupt files**: `read_cycles` skips bad lines (`:136-138`); `read_config` returns None (`:157-160`); `review_inbox` drops a run that raises (`:496-499`). Finding 10 is the one spot where a single bad approvals entry drops a run.
- **Ordering**: `review_items` is highest version first (`:452`); `review_inbox` keeps runs-list order and stable-sorts `decided` live-first (`:506-508`) — matches the docstring and the frontend's `inboxRows`/`pendingOrder`.
- **`by_attack` / majority**: store emits `{v: {sid: [bool…]}}` (`:232-236`), only for versions present in `landed`; the loop's rule is `sum(hits) * 2 > len(hits)` (`chaos/loop.py:763`); `matrixCell` is `hits.filter(Boolean).length * 2 > hits.length` (`derive.ts:1294`). Identical, including ties → blocked. Empty list → loop: not landed; UI: "not measured" (unreachable, `samples ≥ 1`).
- **`mode` refusals**: `preflight` (`api/loop_ctl.py:372-390`) → 400 with nothing to measure, 503 keyless; `start` → `RuntimeError("running")` → 409 under `runs_lock` (`:427-429`), which also stops a measurement and a scheduled run from overlapping. `vulnerability` has no run-id field and `_live_run_measurement` reads `run_manifest("live")` (`:405`), so a history run cannot be measured. The UI mirrors this in `measureBlocker` (`derive.ts:1348`).

## Frontend

- **Partial data**: `matrixCell`/`matrixMode`/`landedLine` are null-safe on `vuln`, `by_attack`, and missing version keys (`derive.ts:1291-1307`); `review_items` emits `gate: null` for rollback copies and `Review.tsx` reads it through `derive` helpers; `agent: null` groups render a placeholder tile (`Review.tsx:158`) and `inboxKey`/`inboxName` handle null. An inbox that does not know the run falls back to the run's own files (`Review.tsx:222-224`).
- **usePoll**: no effect loops found; `refresh` callbacks are stable (`usePoll.ts:84`); render-time state adjustments in `Editor` (`:257-263`) and the orbital component (`:70-74`) are guarded and settle in one pass. Finding 1 is the one real gap.
- **Redirect**: `reviewRoute` (`routes.ts:83-93`) requires `ID.test(run)`, `q.has("v")`, integer ≥ 0; anything else is the inbox. `Number("0x10")` = 16 is accepted and then canonicalised by `redirectLegacy` — harmless.
- **Measure**: disabled with a reason for history/golden, keyless, loop running, old API (`derive.ts:1347-1354`); `isMeasuring` (`:1357-1361`) covers the row flag, the loop's settings mode and the status line.
- **Code organisation**: no `monogram`, no old review-queue reader, no `ReviewQueue` leftovers (grep across `web/src`, `api`, `chaos`, docs). Every new `derive.ts` export has a call site in a page or `RunResults.tsx`. Build and lint clean.
